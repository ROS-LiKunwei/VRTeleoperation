# FA IK 离线参数优化记录（2026-07-21）

## 数据来源

- IK 原始记录：`Log/ik/fa_ik_2026-07-21-10-16-49.369_pid140919.csv`
- 遥操作运行日志：`Log/beavr_run_2026-07-21-10-16-49.104.log`
- 回放求解器：当前重新编译的 `ik_7dof_pybind`，使用同一 URDF、SRDF、目标位姿和关节初值。

CSV 共 312 次求解、72 个目标时间戳。全部记录的 `hand_side` 都是 `left`，因此本次只能对左臂舒适位姿做数据驱动调整。左右 IK 客户端曾在同一毫秒创建同名文件，右臂文件被覆盖；现已在文件名中加入客户端编号，后续运行会分别保留双臂数据。

## 原始表现

原配置为 `max_iters=1000`、`eps=0.01`、可接受误差 `0.04 m / 0.1 rad`。312 次原始记录的统计如下：

| 指标 | 均值 | P50 | P90 | 最大值 |
| --- | ---: | ---: | ---: | ---: |
| 求解耗时 | 5.18 ms | 0.21 ms | 18.73 ms | 20.61 ms |
| 迭代次数 | 321.7 | 9 | 1000 | 1000 |
| 位置误差 | 0.0334 m | 0.0163 m | 0.0807 m | 0.1696 m |
| 姿态误差 | 0.0973 rad | 0.0940 rad | 0.1295 rad | 0.4327 rad |

大量难解样本运行到 1000 次，但增加迭代并没有提高可达覆盖率。运行日志中还存在大量 PICO 数据间隔告警，因此当次遥操作频率的主要瓶颈不是优化后的 IK 计算时间。

## 离线搜索结果

搜索范围包含 `max_iters=25..1000`、多组零空间权重和左臂舒适位姿。为避免把回退搜索误当成独立目标，精度覆盖率使用每个时间戳最初的最多三次多种子调用，共 200 次；耗时统计使用全部 312 次调用。

- `max_iters=50` 时，`0.02 m / 0.05 rad` 覆盖率为 91.0%。
- 外层执行门限为 `0.06 m / 0.12 rad` 时，原始多种子调用覆盖率为 95.5%。
- 从 50 次增加到 1000 次没有提高覆盖率，只小幅改变难解回退样本的残差。
- 新配置在 312 次回放中的平均求解耗时为 0.33 ms，P90 为 0.52 ms，最大值为 0.96 ms。
- 左臂精确样本关节中位数配合 `comfort_nullspace_weight=0.04`，比原舒适位姿的姿态误差 P90 更低；权重继续增大会增加舒适姿态对末端任务的干扰。

## 最终配置

| 参数 | 调整后 | 原因 |
| --- | ---: | --- |
| `ik.max_iters` | `50` | 50 次以后可达率不再增加，避免难解样本占用控制周期。 |
| `ik.eps` | `1e-3` | 作为未加权 SE(3) 末端误差范数的 C++ 停止条件。 |
| `ik.acceptable_position_error_m` | `0.02` | 标记质量较好的近似解，不代替 `eps` 提前停止。 |
| `ik.acceptable_orientation_error_rad` | `0.05` | 与位置阈值共同筛选高质量近似解。 |
| `comfort_nullspace_weight` | `0.04` | 降低零空间姿态对末端跟踪的影响。 |
| `comfort_left_arm_positions_rad` | `(-0.6719, 0.8617, -0.8680, -1.1087, -0.2688, -0.0458, 0.0899)` | 左臂高精度样本的逐关节中位数。 |
| `comfort_right_arm_positions_rad` | 保持原值 | 本次没有右臂 CSV，不能可靠拟合。 |
| `ik_max_position_error_m` | `0.06` | 外层执行门限，在精度和连续可达之间折中。 |
| `ik_max_orientation_error_rad` | `0.12` | 外层执行门限，避免接受明显姿态偏差。 |
| `max_ik_solution_jump_rad` | `0.3` | 允许日志中的 0.215、0.238 rad 连续调整，继续拦截大于 0.3 rad 的明显跳解。 |
| `min_snap_expected_duration_s` | 保持 `0.2` | 当前日志没有 min-snap 规划耗时及限速拒绝统计，缺少调整依据。 |
| `ik_cartesian_position_deadband_m` | 保持 `0.01` | 本次 71 个目标变化中仅 1 次同时落入现有双死区，缩小死区不能改善本次频率。 |
| `ik_cartesian_orientation_deadband_rad` | 保持 `0.06` | 与位置死区同时满足才跳过 IK，本次不是频率瓶颈。 |

`acceptable_*` 是求解器内部近似解质量线，`ik_max_*` 是遥操作控制器是否执行结果的外层安全线，两层用途不同，不能合并为同一个阈值。

## 限制与下一轮验证

本次结果是针对这段左臂轨迹的最优组合，不代表整个双臂工作空间的全局最优。下一轮应确认生成两个带 `_clientN` 后缀的 CSV，再分别统计左右臂；若要继续优化 `min_snap_expected_duration_s`、速度和加速度，还需要同时采集 min-snap 节点的 `plan_timing`、限速和轨迹拒绝日志。
